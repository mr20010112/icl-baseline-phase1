# ContextFlow reproduction runner

Implements the active `contracts/baseline/v2.yaml`. Both v1 and v2 are **already frozen** in `contracts/.registry.json`; v1 is retained only for the version chain. Operators must not create, edit or re-freeze any protocol by hand. The sole owner-authorized exception is a disclosed limit successor created by tools/amend_limits.py; fresh batch code review is required. Return any needed change to the project owner as a new version. Preserve all existing frozen protocol bytes; only the sanctioned tool may append successor registrations. Real execution still requires verified resources, independent review and budget authorization. No training, evaluation or downloads were performed. See [operator handoff](../../handoffs/third-party/README.md).

`tools/research.py run --job experiments/baseline-seed42.json` launches the runner with the registered ContextFlow Python 3.11. It reads the launch manifest, `RESEARCH_CONFIG`, and resources by job ID. Project imports and both probe entries come from the reviewed code snapshot. The official checkout must be clean at `c6dee891f0afd520aec5a8869891e9b06b99f856`; it is read only. Its LIBERO client uses a separate Python 3.8 interpreter. Machine paths belong in the resource registry and environment.

Checks a–c cover checkout identity, dataset identity/official held-out split, interpreter/official config parsing, and pre-cached weights/tokenizer. Numbered step logs, `details.json`, `leakage.json` and hash inventories preserve evidence. `--dry-run` performs only these checks and prints normalization, training, probe server and all four evaluation commands, including environment overrides. If registration fails, it still prints the plan, with explicit placeholders for unregistered interpreters. It never normalizes, trains, starts a server, samples a GPU, copies checkpoints or evaluates. Use a fresh directory:

```bash
timeout 600 env PYTHONDONTWRITEBYTECODE=1 python3 baseline/runner/contextflow_repro.py \
  --seed 42 --dry-run --job experiments/baseline-seed42.json \
  --run-dir /tmp/contextflow-check-UNIQUE
```

Official normalization/training run in `runs/<task_id>/work`, keeping relative assets and offline WandB output there. Training uses the official `--checkpoint-base-dir "$CONTEXTFLOW_CHECKPOINT_SCRATCH"` override. Scratch must be an absolute directory outside both run and official checkout, with no pre-existing `ContextFlow/<task_id>` experiment. The official `save_interval=5000`, `keep_period=5000` and final step 19999 are unchanged. Other steps and optimizer state stay on scratch. The runner copies **only** step 19999 `params/` and `assets/` to `runs/<task_id>/checkpoint/19999/`, compares every relative filename, byte size and SHA256, and writes `checkpoint/checkpoint-sha256.json`. It checks the copied payload again after evaluation. Both passes load this copied checkpoint. The launcher includes these physical files in `artifacts.json`.

The method-to-code map uses official paths relative to that checkout. Wrapper symbols below are in `baseline/runner/`; independent reviewer acceptance remains pending.

`eval/server-requests.jsonl` stores per-request ID, task/index, demo episode indices, latency in ms and any official inference exception type. Failed inference calls are logged and their original exceptions are re-raised unchanged; missing demo observations invalidate diagnostics. `eval/{unseen,all_tasks}/` holds separate official JSON, videos and client trial JSONL. `details.json:trials` adds each trial's task, official success, step counts, failure step, request IDs/full observations, demo indices and latency count/median/p95. `details.json:tasks` contains only the unseen 50-trial pass; `all_tasks` retains all second-pass rows separately.

`steps` counts completed direct `env.step` calls **including** the 10 settling steps; `policy_steps` and `settling_steps` are also recorded. `failure_step` is null on success. Otherwise it is the one-based last attempted step at the official horizon, the raising step for an env.step exception, or the next step for an exception before env.step. No extra simulation is performed. Official output lacks these counts, hence the client observer. Truncated or inconsistent trials/results fail verification.

`metrics.json` contains the nine v1 names plus `seen_avg_success`, `infer_latency_ms_median`, `infer_latency_ms_p95`, `unseen_mean_steps_success`. Only the 16 seen rows (8/suite) at 20 trials contribute to seen success. Second-pass unseen rows never enter primary/signal or latency/step metrics. Latency median/p95 use linear interpolation at `(n-1)*q` over requests from the unseen pass. Successful unseen episodes are pooled for mean steps; no successes yields -1 and `details.json:no_successful_unseen_episodes=true`.

Training GPU-hours are monotonic training subprocess seconds / 3600 × one GPU, excluding normalization/evaluation. GPU memory is maximum sampled whole-device used memory from `nvidia-smi`, approximately every 2 s, converted from MiB to decimal GB. Sampling can miss transient peaks and includes other GPU users; use an exclusive GPU. The launcher conservatively reserves 60 GPU-hours per whole job, without refund, up to six attempts (360 GPU-hours / 1296000 CPU-seconds).

The runner sets registered `LEROBOT_HOME`, official `PYTHONPATH`/`OPENPI_PROJECT_ROOT`, disables bytecode and HF online access, sets training memory fraction 0.9 and server float32 matmul precision. Complete, non-expired official weights/tokenizer caches are required before any pipeline process. The official download helper does not honor HF offline flags, so cache checks remain essential.

Verification is CPU-only fixture coverage and a local dry-run stopping at missing dataset registration. Official interpreter imports/CLI, dataset/cache usability, real simulator hooks, checkpoint size, training, serving and cross-machine transfer remain unverified on operator hardware. Both protocols are already frozen; existing resource, review and budget gates remain mandatory before launching these jobs.
