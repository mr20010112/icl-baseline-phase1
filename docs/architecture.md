# 架构与状态所有权

本项目以 ARIS Markdown skills 和原生产物为主，只补科研证据与运行可靠性所需的连接。目标是合作研究者能检查的文件工作区，不是自动证明科学真实性的系统。

| 信息 | 唯一事实来源 | 可变性 |
|---|---|---|
| 阶段进度/接受记录 | `.aris/runs/*.json`（上游 run_state） | 原生状态 API 更新 |
| 当前 idea 的工作上下文 | `idea-stage/docs/research_contract.md` | 随进度更新，引用冻结协议 |
| 判据与预注册实验设计 | `contracts/<idea_id>/vN.yaml` + 冻结登记 | 原版本不改；新版本单独创建 |
| 每次实际执行 | 运行产物目录中的 manifest、日志、原始指标、快照 | 完成后按证据保留 |
| 候选、评审与选择 | `idea-stage/`，原始响应留痕 `.aris/traces/` | 新轮次追加，不覆写历史证据 |
| 论文的数值与结论 | `paper/` 的 claim ledger 引用运行和分析 | 证据变化后重新审计 |
| 研究经验 | `research-wiki/` 或原生 Findings 文件 | 记录失败原因与适用边界，按需检索 |
| 当前恢复摘要 | 恢复入口生成视图 | 从上述来源生成，不另造阶段状态 |

阶段状态不在 README、CLAUDE.md、AGENTS.md 各维护一份。README 是入口，两个宿主文件引用共同规则。运行状态与科研阶段分属不同粒度：任务“完成”不等于阶段“接受”。

## 协议边界

冻结协议描述未来如何判断；工作契约说明目前做到了哪里。分析文档解释已经观察到什么。三者相互引用，不用分析结果改写过去的判据。协议 fingerprint 检查用于检测误改和产物绑定，假定合作操作者；它不是防篡改公证。

baseline 复现也有自己的冻结协议。它先验证数据、环境、split、评测、seed 和预定复现容差，才成为后续比较锚点。论文原值与复现均值/方差分栏。硬件不同按预定统计方案解释差异，不保证逐位一致。

新的接受链由 `tools/results.py` 核验稳定signal和逐项判定，`tools/run_evidence.py`统一核验完整运行产物，baseline与论文审计共用这些检查。result-review receipt绑定分析SHA、冻结协议和全部run材料；分析本身不引用receipt，避免哈希循环。claim和baseline验证记录持有receipt引用。协议版本升级保留signal含义，改变判据使用新ID；历史冻结文件不自动迁移。

`tools/selection.py`校验完整候选池、独立评分、全体排名和revise处理，selection_record是architect选择的结构化记录。执行评审使用规范化execution binding，包含命令、入口、配置、代码、资源与相关决策指纹，排除回填receipt及task/retry标识。worker从代码快照启动入口，执行前后重核绑定与快照。该机制约束可复查执行范围，不能推断任意动态Python依赖都已隔离。

## 角色路由

偏好在配置中，实际接入在运行时解析。能用的 CLI/API/MCP 才调用；无法接入则导出人工交接包并导入原始结果。请求别名、实际身份、family、身份依据、会话和独立性都需记录。传输成功不等于 reviewer 范围完成；同 family 或身份未知不自动提升为跨模型通过。

## 路径与依赖

上游固定版只读保留许可证，与 `docs/`、`configs/`、`tools/` 等项目补充隔离。项目内相对路径优先；迁移后执行初始化入口重建宿主发现链接和 helper 链接。大数据和权重只登记位置与版本，不复制入项目包。远程 provider 细节留在资源登记和交接包，不伪造可用服务器。

## 能力边界

门禁能发现证据缺失、协议误改、指标缺失、运行失败和预算不足；无法自行证明数据无泄漏、方法科学有效、文献穷尽或模型身份诚实。此类语义判断交给读取原始材料的独立评审，并保留未完成状态。离线 toy 不调用商业模型，不验证 SSH/tmux/调度器/MCP，也不证明真实 baseline 可复现。
